# Role & Objective

You are a senior software engineer tasked with fixing a deliberately planted bug in a meeting room booking system and executing comprehensive validation of the completed fixed project. Your goal is to analyze the buggy project, create a corrected version in a new directory, and thoroughly validate that all functionality works correctly without errors.

# Inputs & Context

**Original Buggy Project Location**: `issue_project/`
```
issue_project/
├── src/
│   ├── __init__.py
│   ├── models.py
│   ├── booking_system.py      # Contains the bug
│   └── utils.py
├── tests/
│   ├── __init__.py
│   └── test_booking.py        # 2 tests currently FAIL
├── data/
│   └── sample_data.json
├── requirements.txt
├── README.md
└── KNOWN_ISSUE.md             # Detailed bug analysis
```

**Bug Description**:
- Type: Functional Bug - Feature doesn't behave as specified (ignores constraints)
- Location: Equipment validation logic in the booking system
- Symptom: The system incorrectly approves meeting room bookings when the room has SOME but not ALL of the required equipment
- Current Test Status: 2 tests FAIL, 2 tests PASS

**Target Workspace**: Create fixed project under `grok-fast/fixed_project/`

# Step-by-Step Instructions

## Phase 1: Project Analysis & Setup
1. Read and understand the original `issue_project/` structure
2. Review all test cases in `tests/test_booking.py` to understand the expected behavior
3. Read the bug documentation in `KNOWN_ISSUE.md`
4. Identify the exact location and root cause of the equipment validation bug

## Phase 2: Create Fixed Project
1. Create directory structure: `grok-fast/fixed_project/` with all subdirectories (src, tests, data)

2. Copy all files from `issue_project/` to `grok-fast/fixed_project/`:
   - `src/__init__.py`, `src/models.py`, `src/utils.py`
   - `src/booking_system.py` (will be fixed)
   - `tests/__init__.py`, `tests/test_booking.py`
   - `data/sample_data.json`
   - `requirements.txt`

3. Fix the equipment validation bug in `src/booking_system.py`:
   - Change the validation logic from accepting PARTIAL equipment matches to requiring ALL equipment
   - Use set operations (e.g., `issubset()` or set difference) to ensure required_equipment is a subset of room.equipment
   - If equipment is missing, include missing items in the error message
   - Keep the fix minimal (1-5 lines of code change)

4. Create `grok-fast/fixed_project/README.md`:
   - Project overview and what was fixed
   - Quick start instructions
   - How to run tests

5. Create `grok-fast/fixed_project/FIX_SUMMARY.md`:
   - Bug description and root cause
   - The specific code change with line numbers
   - Before/after code snippets
   - Test results (before vs. after)
   - Use relative paths only

## Phase 3: Complete Environment Setup
1. Install Python dependencies: `pip install -r requirements.txt` (pytest>=7.4.0, python-dateutil>=2.8.2)
2. Configure and create a Python virtual environment if needed
3. Ensure all modules can be imported without errors

## Phase 4: Execute Full Validation
1. **System Launch Test**:
   - Verify all modules import successfully (src.models, src.booking_system, src.utils)
   - Confirm no import errors or runtime exceptions
   - Test basic system instantiation

2. **Automated Test Execution**:
   - Run `pytest tests/ -v` (verbose output)
   - Capture full test output with all test names and results
   - Verify all 4+ tests pass (the 2 originally failing + 2 originally passing + any additional tests)
   - Ensure 0 test failures

3. **Functional Validation Tests** (execute at least 3 smoke tests):
   - **Test 1 - Partial Equipment Rejection**: Create room with only PROJECTOR, attempt booking requiring PROJECTOR + VIDEO_CONF, verify booking fails with error message listing missing items
   - **Test 2 - Complete Equipment Approval**: Create room with PROJECTOR + VIDEO_CONF, attempt booking requiring both items, verify booking succeeds
   - **Test 3 - No Equipment Requirement**: Create and book room without equipment requirements, verify booking succeeds
   - Capture all outputs

4. **Validation Checklist**:
   - All modules import without errors
   - System instantiates without exceptions
   - All automated tests pass (exact count required)
   - Equipment validation correctly rejects partial matches
   - Equipment validation correctly approves complete matches
   - Error messages list missing equipment items clearly
   - All functionality behaves consistently

5. **Comparison Verification** (optional but valuable):
   - Run original `issue_project` tests to confirm they still fail
   - Document the before/after comparison
