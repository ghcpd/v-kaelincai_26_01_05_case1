# Role & Objective

You are a senior software engineer tasked with fixing a deliberately planted bug in a meeting room booking system and performing comprehensive validation of the completed project. Your goal is to analyze the buggy project, identify the issue, create a corrected version in a new directory, and thoroughly validate that all functionality works as expected.

**Original Buggy Project Location**: `issue_project/`
```

├── src/
│   ├── __init__.py
│   ├── models.py
│   ├── booking_system.py      # Contains the bug
│   └── utils.py
├── tests/
│   ├── __init__.py

├── data/
│   └── sample_data.json
├── requirements.txt
├── README.md
└── KNOWN_ISSUE.md             # Detailed bug analysis
```

**Bug Description**:
- Type: Functional Bug - Feature doesn't behave as specified (ignores constraints)
- Location: Equipment validation logic in the booking system
- Symptom: The system incorrectly approves meeting room bookings when the room has SOME but not ALL of the required equipment
- Current Test Status: 2 tests FAIL (`test_bug_partial_equipment_match_should_fail`, `test_bug_client_meeting_scenario`), 2 tests PASS

**Target Workspace**: Create fixed project under `oswe-mini-m23a2s165/`

# Step-by-Step Instructions

## Phase 1: Analysis
1. Read and understand the original project structure in `issue_project/`
2. Review all failing test cases in `tests/test_booking.py`
3. Read the bug documentation in `KNOWN_ISSUE.md`
4. Identify the exact location and root cause of the equipment validation bug

## Phase 2: Implementation
1. Create a new directory structure `oswe-mini-m23a2s165/fixed_project/` with the following layout:
   ```
   fixed_project/
   ├── src/
   │   ├── __init__.py
   │   ├── models.py
   │   ├── booking_system.py     # Copy and FIX the bug here
   │   └── utils.py
   ├── tests/
   │   ├── __init__.py
   │   └── test_booking.py
   ├── data/
   │   └── sample_data.json
   ├── requirements.txt
   ├── README.md
   └── FIX_SUMMARY.md
   ```

2. Copy all files from `issue_project/` to `oswe-mini-m23a2s165/fixed_project/`

3. Fix the equipment validation bug in `src/booking_system.py`:
   - Modify ONLY the equipment validation logic
   - Ensure the validation checks that ALL required equipment is present (not just SOME)
   - If any required equipment is missing, the booking must fail with an error message listing the missing items
   - The fix should be simple (1-5 lines of code change)

4. Create `oswe-mini-m23a2s165/fixed_project/README.md`:
   - Project overview (fixed version)
   - What was fixed
   - Quick start guide
   - Test execution instructions
   - Confirmation that all tests pass

5. Create `oswe-mini-m23a2s165/fixed_project/FIX_SUMMARY.md`:
   - Bug description
   - Root cause analysis
   - The specific code change made (with line numbers)
   - Before/after code snippets
   - Test results comparison (before: 2 failed; after: 4 passed)
   - Use relative paths (e.g., `src/booking_system.py`, not absolute paths)

## Phase 3: Full Validation
1. Set up the Python environment:
   - Navigate to `oswe-mini-m23a2s165/fixed_project/`
   - Install dependencies: `pip install -r requirements.txt`

2. Run environment smoke test:
   - Create and execute a smoke test script that:
     - Instantiates the booking system
     - Creates a room with partial equipment (e.g., only PROJECTOR)
     - Attempts to book it with a request requiring multiple equipment items (e.g., PROJECTOR + VIDEO_CONFERENCE)
     - Validates that the booking fails (success=False)
     - Validates that the error message lists missing equipment (e.g., "Missing equipment: video_conference")
     - Confirms no runtime errors occur during execution

3. Run the full automated test suite:
   - Execute: `pytest tests/ -v` (with verbose output)
   - Capture complete output showing all test results
   - Verify all 4 core tests pass (the 2 previously failing + 2 previously passing)
   - Additional tests may exist; all must pass

4. Verification Checklist:
   - System launches successfully without import errors or exceptions
   - All automated tests pass (0 failures, all passed)
   - Equipment validation correctly rejects bookings with missing required items
   - Error messages clearly identify which equipment is missing
   - Project behavior is consistent across all test scenarios
